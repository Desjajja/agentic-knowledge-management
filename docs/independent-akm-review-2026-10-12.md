# AKM 独立只读评审与优化建议

日期：2026-10-12。评审者：独立 subagent `/root/independent_akm_review`。

本轮只读取代码、原始资料、知识页、测试与现存 trace；未运行测试、未发起新的模型请求、未修改实现或知识库。主 agent 仅将报告整理落盘。旧英文基线、中文副本、工具链验证分别评估，不混作同一次实验。

**结论：AKM 已证明真实归档和有证据回答可以跑通，但完整工作场景、来源保真和工具化成本收益尚未充分验证。优先做证据聚合工具、关键限定保护与真实场景回归；增加通用工具数量本身不能保证省 token 或降低时延。**

## 1. 知识构建内容水平

### 会影响实现的语义失真：更小与非递增

原文 `artifacts/distributed-systems-2026-10-12/inputs/s2.md:158` 要求拒绝 token “gone backwards”，例子是处理 34 后拒绝 33。归档页 `.../projects/分布式系统/Fencing Tokens for Safe Distributed Locking.md:31` 却写成拒绝 “non-increasing tokens”。

“非递增”包含相等，比原文要求更强。同一租约内多次写入携带相同 token，按该表述可能被误拒绝；原文没有给出这条规则。中文副本、q01/q02 和最新中文回答继承了该错误。

核心机制提取正确，不等于实现细节保真。比较符号、量词、必要/充分条件应单独检查；翻译不能修复上游事实错误。

### 限定保留有亮点，但丢失了争议与更新

保留较好的内容包括：

- Linearizability 更新融合了 Kleppmann 与 Jepsen，保留原例子和两份来源。
- Snapshot Isolation 保留 classic/strong 与 generalized/weak 的定义区别，没有统一写成“SI 永远弱于可串行化”。
- Strong Serializability 保留事务原子性、多对象、实时顺序与系统范围。
- q15 没有把 2015 年文章外推为 PostgreSQL 18.1 当前集群保证。

但 `inputs/s2.md:340` 的 2016-02-09 rebuttal 更新未进入四个分布式锁知识页：作者承认反方有合理观点，并提醒双方博客未经学术同行评审。派生页使用了较强的通用断言，包括“唯一稳健的修复方法”。日期和作者 attribution 不足以替代争议状态。至少应保留原文已有的反驳和限定提醒。

### 粒度和关系

6 篇原文生成 13 页：s1 创建 6 页、s2 创建 4 页、s3 更新 Linearizability、s4–s6 各创建 1 页。CAP 总览与概念页有合理性；分布式锁的暂停/延迟、fencing、Redlock 页面重复同一安全论证，容易使 top-k 被同源页面占据。

不宜按页数机械合并。建议评价独立任务价值、重复事实比例、top-k 同源占比、用户需确认的条目数。

`related` 缺失也有协议原因：`src/pi.js:107` 只允许引用 CONTEXT 中的既有页面；同一次新建的四页无法按该协议相互关联。而底层提案系统支持同批次关系（`src/knowledge.js:121`、`tests/knowledge.test.js:76`）。提取协议和存储能力未对齐。

## 2. Retrieve 和回答评估

### 零命中时工具无法救场

旧英文基线的中文释义 q03、q07 零命中。`src/pi.js:128–129` 初始检索为空就直接返回，后面的 pi 搜索工具与“搜索原术语”提示不会执行。工具只能补充已有召回，不能恢复零命中问题。

### 原评测统计和评分需要复核

- 原报告写“14 次实际问答”，实际 `model-calls.json` 是 **6 次提取＋12 次问答＝18 次模型调用**；其余 4 题直接返回。
- q12 不应因未召回预定的 Linearizability 页而扣分：实际答案已经引用 Many Systems 页中的 quorum、线性一致性和少数侧不可用证据。证据见 `queries/q12-answer.json:16` 及该知识页 `:45–47`。应按内容充分性上调。
- 不能据此直接提高整体分数。q01/q02 的 token 比较条件失真，在严格来源保真标准下应降为部分正确。应保留原评分，另存复核意见，再按统一分项标准重算。
- q13/q15 是“话题相关但具体事实缺失”，不等同于完全无关的 q14。召回近似资料再拒答可能是正确流程，不宜一律要求空结果。

建议分开评分：核心事实、实现细节、限定完整性、引用支持度、证据缺失时的行为。不要仅凭来源或指定页名生成 gold relevance。

新工具实验实际完成 1 search＋4 read，但 `scripts/validate-knowledge-tools.js:7` 使用旧英文 Vault，`:15` 明确要求按 2000 字符读完整篇，`:17` 未记录 usage 和耗时。它只证明工具链能运行，不能证明自然问题下的自主选择、中文回归或性能收益。

当前能成立的结论是“首轮正文预算下降”；尚不能成立的是“总 token 更少”“整体更快”。

## 5. 固定工作流封装成 tool 的优先级

核心原则：固定控制流和确定性操作由 tool 承担；模型保留概念判断、冲突解释和回答。不要把每个小步骤都暴露给模型增加调度轮数。以下名称均是建议，尚未实现。

| 优先级／候选 | 一次调用完成 | 预期收益 | 边界和风险 |
|---|---|---|---|
| **P0 `akm_retrieve_evidence`** | 同项目多查询、排序融合、同源去重、命中章节读取、citation/hash/预算打包 | 代替 search→逐页 read→分页，减少模型往返与重复历史传输 | 保留原文段落和位置；预算不足明确标记；工具不悄悄总结事实 |
| **P0 `akm_proposal_review`** | 编号选择、metadata 修改、剔除、合并、来源并集、diff 与关系校验 | 外部 agent 不必反复编辑 JSON、重建提案，减少宿主上下文 | 修改形成待确认 revision；commit 仍需要准确 revision＋labels；合并不丢来源 |
| **P1 `akm_find_candidates`** | 按概念批量查询、标题/alias 精确匹配、项目限定、候选章节与 hash | 替代整篇前 8000 字符搜 top-5 全文，减少无关旧页输入 | 检索只产生候选，不能凭词法相似度自动覆盖或合并 |
| **P1 `akm_prepare_source`** | 格式/编码检查、hash、重复上传检测、章节分块、来源定位 | 重复或局部变化不必全量交给模型 | 2MiB 输入上限不等于模型上下文容量；跨块限定要保留；摘要不是原始证据 |
| **P1 `akm_plan_merge`** | 内容差异、重复事实、矛盾、来源与关系变化，生成合并规划 | 将多次全文阅读改成一次审阅规划 | 冲突判断仍需模型或人；不直接正式写入 |
| **P2 `akm_query_batch`** | 冻结语料、多题检索、证据去重缓存、限并发回答 | 复用页面读取/tokenization，服务 benchmark 与批量任务 | 每题独立证据与 usage；共享 session 不保证省 token |

当前演示的单篇约 6796 字符，本可一次有界读取；强制 2000 字符造成四轮。假设最终读取相同全文且调用串行，聚合工具可将 5 次工具调度降到 1 次；节省的是中间模型往返，不是全文本身。这是结构估算，不能写成已测得的性能改善百分比。

优先实现一个证据聚合 tool，并同时供 pi 和外部 agent 使用。外部 Codex 只需证据时直接拿结构化结果；明确委托 AKM 回答时才调用内部模型，避免两个模型重复总结。

## 6. pi SDK 能力的合理边界

已参与：workspace-local provider 配置、模型适配、session abort、custom tools 执行、多轮工具消息。pi 并非只有 API 转发。

未参与：持久 session memory、skill 加载、extensions、自动 compaction/retry。当前使用 in-memory session，资源列表为空，compaction/retry 关闭（`src/pi.js:37–47`）。知识记忆由 Vault、来源、提案和事务提供。

建议优先采集 SDK 的每轮消息和 tool_execution 事件，将固定步骤放进 AKM tool。短任务不必贸然引入长期 session 或压缩，它们可能携带陈旧上下文或丢失证据；大型多文档任务再单独评估可恢复 session。Skill 描述调用与审核契约，tool 实现业务流程，二者不能互相替代。

## 7. 建议验证实验和准入标准

### P0：可信评分与成本账本

保留旧评分，新增复核；三套语料/工具路径分别记录。每次保存模型、语料 hash、prompt/tool 版本、每轮 usage、请求数、模型/工具耗时、端到端耗时和失败。

加入保真案例：`<` 与 `<=`、“通常”与“总是”、作者观点与共识、文末反驳/勘误、后续事实与历史事实。

准入建议：关键条件失真为 0、无伪造引用、正式提交需确认、统计由运行记录计算。

### P0：证据聚合 A/B/C

- A：较大首轮全文。
- B：小首轮＋模型自由 search/read。
- C：批量证据聚合＋必要补读。

同模型、同语料、自然问题，不强制工具序列；多次重复，记录全部轮次 token、总时延 p50/p95、回答事实/限定/引用质量。

建议门槛：质量不退步，总输入 token 中位数下降至少 20%，端到端中位时延下降至少 15%；p95 不应明显恶化。**这些是建议门槛，不是已经获得的收益。**未达标则只报告能力改善。

### P1：完整工作场景回归包

1. 含建议、撤回、最终确认和无关私密信息的长对话，经历修改＋合并＋剔除，再归档召回。
2. 同主题多来源资料，包含重复上传、矛盾、修订、文末关键限定。
3. 两个项目有同名概念，检验默认关系和迁移依赖契约。
4. 中文原问题、英文术语、中文释义、完全无关问题、话题相关但事实缺失问题。
5. 外部 agent 在其他 cwd 按 skill 完成选择、归档和引用；独立验证并发等待/取消。

准入建议：任务闭环完成、合并保留来源、重复上传不增加重复知识、hash 冲突不覆盖、项目依赖契约一致。

**行动顺序：先建立可信评分与全轮成本测量；再做证据聚合 tool，并补来源限定保护和合并审核闭环；最后评估语义检索与长期 session。**
