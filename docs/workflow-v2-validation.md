## 四阶段实现

| 阶段 | 已落地能力 |
|---|---|
| 1 测量 | 累计所有模型轮次 usage、请求/工具/时间，CLI 任务账本持久化；缺失 usage 为 null，已知成本下界另记；reasoning 不重复加到 total |
| 2 取证 | 查询变体 RRF、同源软去重、定义/相关/修订段聚合、批量章节补读、统一字符预算、hash/引用门禁、零命中一次扩展、有界补证 |
| 3 归档 | 原文段落定位、完整 prompt 估算预检、全块处理与跨块协调、来源缓存、保真检查、编号批量编辑、保留来源的合并、同批关系 |
| 4 外部适配 | retrieve/propose/review/commit CLI；skill 由宿主自主判断查询、默认发现 Vault；宿主可直接用证据回答，避免额外内部代答 |

用户视图以编号、正文、项目名、tag/alias/related 和必要冲突为主；机器接口保留内部路径与版本信息。本次代答文本仍会露出补证预算、英文诊断或冗长 wiki 引用，产品层呈现尚需改善。没有实现异步 job 服务、PDF/OCR、两张正式页面迁移合并或自动安装外部 skill。

## 真实增改查：审核后成立

这轮使用真实 `deepseek-v4-flash`、启用 thinking，通过 pi SDK 处理隔离库；Markdown、YAML 属性、来源和 related 实际写入可由 Obsidian 使用的目录。不是 mock，也没有使用 Obsidian GUI 验收插件展示。

1. 订单对话包含被拒绝的助手建议、5 分钟 TTL 撤回和最终决定。模型提出 3 项；将 [2] 合入 [1]、修改标签和关系、剔除待评估发布方案 [3]，提交 1 张笔记，保留 2 个支持来源。
2. 原始 Kleppmann 锁文章提出 5 项。提交门禁指出 4 项漏争议背景；人工补 2016-02-09 反驳、非同行评审限定，明确更小 token 与相同 token 的区别，限定 safety 与 progress。5 张笔记、17 条项目内 related 均实际落盘并指向存在页面。
3. 同一资料改名再上传复用提案，没有模型调用、页面数不变。仅验证顺序幂等，不能推广为同源并发 single-flight。
4. 新对话明确版本展示、恢复失败显示状态未知。真实模型生成完整更新提案，未人工改正文直接审核提交；旧事实和撤回记录保留，来源从 2 条增为 3 条。
5. 三道召回分别回答 TTL/恢复/版本条件、更小 vs 相同 token/检查端/争议更新、生产精确吞吐缺失；主审和独立评审均为 3 正确、0 部分、0 失败。
6. `/tmp` 中调用另一个目录的 CLI，依靠 AKM_HOME 找到根目录；完整复制根目录到新位置后仍可检索，无需重新生成知识。

共 6 个模型 session、9 个实际请求、62,735 total tokens、43,370 输入上下文 tokens，7 次工具调用其中 5 次被预算门禁拒绝。工具门禁控制了循环，但错误尝试仍消耗下一轮上下文，不应当作免费优化。详见场景 `manual-evaluation.json`。

## 冻结语料质量：分开处理内容失真与召回失败

英文原库与中文副本各 13 张知识页、同一批 6 篇公共来源、同一组事先固定的 16 题；旧库未修改来提高成绩。评分按原始来源事实、比较条件、重要附加主张、引用及最终可用答案：2 完全正确、1 部分、0 失败。两组均为 26/32 分，具体缺陷不同。

## A/B/C：聚合工具尚未带来收益

同一冻结英文库、同一 provider/model/thinking，两个自然问题（q01 英文、q03 中文）各重放 5 次。每轮交错策略顺序、顺序请求并间隔 5 秒，减少并发竞争；问题内时延不含刻意的任务间等待。

- A：13 页全文，一次模型请求，无工具。
- B：词法 top3，每页前 4,000 字符，自由 search/read，最多 4 请求。
- C：top3 聚合证据、零命中扩展、最多一轮补证，最终 hash/引用/协议门禁。

| 策略 | 正确 / 部分 / 失败（各 10 槽） | 返回答案的输入 token 中位数 | 返回答案的端到端中位时延 | 请求中位数 |
|---|---|---:|---:|---:|
| A | 3 / 7 / 0 | 10,260 | 9.899 秒 | 1 |
| B | 1 / 6 / 3 | 7,130 | 6.809 秒 | 3 |
| C | 2 / 7 / 1 | 15,696 | 14.046 秒 | 3 |

A/B/C 所有“部分”都继续传播原库非递增条件；C q01 第 1 次因错误引用失败，B q03 第 2/4/5 次因请求预算用尽失败。失败槽不补抽成功样本。A/B 直接走 runPi，没有 C 的最终发布门禁，其返回引用已人工单独核对；本实验不是保护条件完全相同的算法对照。

上表成功组分母不同，不能直接推出因果收益。6 个三个策略都返回答案的完整配对：输入中位数 A 10,264 / B 9,774.5 / C 15,168.5；时延 A 11.747 / B 8.4715 / C 10.1935 秒。C 输入比 A **增加 47.8%**、比 B **增加 55.2%**；时延比 A 降低 13.2%，比 B 增加 20.3%。没有配对组三个答案均满足严格质量条件。目标“输入降低 20%、时延降低 15%”未达，样本不支持稳定 p95 或跨学科结论。

A 共 10 请求、121,594 total tokens；C 共 23 请求、152,569 total tokens。B 共 29 请求，已知 total tokens 下界 106,342，预算失败产生缺 usage 的 assistant 轮次，完整总数为 null，不填零。这也说明失败可能让成功组中位数看起来更便宜。

冻结双语＋ABC累计 70 个 session、127 个实际请求，已知 total tokens 下界 898,796；完整总数缺失不补猜。126 个请求记录 HTTP 200，1 个无状态；session 最后 httpStatus 为 200 的数量不能冒充 HTTP 请求数。

## 长文分块：协议完成，质量仍需审核

两篇 Kleppmann 原始文章串联，约 44,429 字符，形成 2 个处理块。首次模型混淆 `paragraphId` 与精确分片 `id`，被严格校验拒绝，消耗 1 请求/20,802 tokens。澄清提示必须复制 `paragraphs[].id` 的冒号和分片后缀后，新目录完成 2 次提取＋1 次协调，3 请求/76,007 tokens；首次失败和新版本指纹均保留。

13 个草稿恰好各进入一个协调组，产出 2 个提案，原文支持分别为 68/86 个定位 span。Redlock 的更小 token 条件、2016-02-09 反驳及非同行评审说明保留。但仍有泛化“放弃所有时序假设”的措辞，需限定 safety/progress；协调把概念草稿合成两篇大页，Redlock 并集达到 27 tags/32 aliases，审核噪声过大。CAP 页被误要求展示同一资料包另一篇 Redlock 的争议背景，说明限定检查应按来源/主张范围而不是整包文本判断。

本次长文仅生成提案，未提交正式知识。真实全块处理和来源定位验证成立，语义保真和最小 metadata 体验不全通过。提取提示修订不改变已完成冻结召回代码；不能把前后不同提示版本混称同一个完整协议。

## 实验暴露的下一步

1. **先保真，再调排序。** 对有比较符、作者争议或后续修订的知识保留可追溯原文；从原来源另起修正提案，审核形成独立修正版库。冻结库继续作为历史回归资产，不能原地清洗后声称提升。
2. **补证按缺口触发。** C 常在已足够的 3 页证据后继续补读，序列化已有正文、工具结果和下一轮消息。缩小默认章节包，回传增量证据，只有明确缺所需段落才补证。
3. **原术语做本地索引。** 中文问题在英文库先走一次模型扩展，再回答/补证，常累计 3 请求。利用 aliases/术语索引及可重建派生数据，避免每次付费翻译。
4. **对宿主优先提供证据工具。** Codex 等宿主已在对话中时，直接 retrieve 聚合证据后由宿主回答；本轮 C 是独立代答路径，不能把它较高成本外推为所有外部调用。
5. **继续限制工作流循环与显示噪声。** 门禁已防住预算外循环，但模型仍尝试已关闭工具；需要更明确的阶段工具暴露与简洁输出格式。当前顺序来源复用不支持并发同源锁。

这些是本轮证据形成的优化方向，不是已经测得的收益。完整参数调整应另起版本，用同一冻结组与修正版组复验，避免边测边改引入混杂。
