日期：2026-10-12。环境：macOS，Node.js v24.19.0，pi SDK 1.1.0。

- 默认根目录、Vault/workspace 自描述与名称/ID 定位。
- 提案新增、稳定编号、属性/正文修改、剔除/暂缓及选择性提交。
- Markdown 页面更新、来源副本、项目索引、来源 ledger、事务备份与恢复。
- 中文/英文显式检索，项目过滤、标题/别名/标签权重和可引用正文行号。

- 通用 Agent skill、真实 CLI demo、固定检索数据集、基线和回归 gate。

`npm test`：**22/22 通过**。其中四项直接运行 pi SDK，对接本地 HTTP/SSE 兼容服务，验证模型隔离、无工具、提案生成、来源片段、错误及超时；没有使用真实商业模型，所以实际提取质量和各家 provider 兼容性仍需之后实测。

`npm run demo`：通过新增 → 查询 → 修改 → 再查询 → 整体根目录移动 → 查询。使用临时目录，从与 Vault 不同的 cwd 调用 CLI；没有初始化真实 `~/.akm` 或修改全局 pi 设置。

## 检索基准

固定合成集：20 文档、40 查询，其中 37 个正例、3 个负例。包括中文、别名、标签、项目过滤、换词、跨项目。graded relevance 为人工预置，尚无真实用户标注集或独立测试集。

| 指标 | 基础 BM25（标题+正文） | 属性加权 BM25 |
| --- | ---: | ---: |
| Recall@3 | 0.7342 | 0.9640 |
| MRR@3 | 0.7568 | 0.9730 |
| nDCG@3 | 0.7488 | 0.9715 |
| 负样本正确率 | 0.6667 | 0.6667 |

增益主要来自 aliases/tags 索引，并不代表已实现语义检索。换词查询组 Recall@3 仍为 0.7333；“光合作用叶绿体”返回不相关页面，体现中文单字 token 带来的误检。保留这些失败样本，不删除它们提高分数。

最终 `npm run benchmark`：通过；总体与各组质量无回归，40 条查询排名与 baseline 一致。基准输出包含 dataset hash、retriever 源码 hash、环境和每查询排名。负例不混入正例的 Recall/MRR/nDCG 平均值。

单次本机排名耗时 p50 约 0.12 ms、p95 约 0.26 ms，仅为 20 文档的内存排名；**不包含扫描、锁、网络或 LLM，不能作为实际系统性能结论**。耗时不参与质量 gate。

回归 gate 的测试已验证：属性权重版本作为 baseline 时，退回基础 BM25 返回退出码 2，并生成完整差异报告。数据 fingerprint 不一致、非法指标、缺失/重复 query、分组数量不一致和聚合指标不一致均被拒绝。

可重跑：

```sh
npm test
npm run demo
npm run benchmark
```

## 独立代码审查

采用只读 reviewer 审查完整工作树。初审发现并实际复现两个 Important 问题：

1. 跨候选项 related 的依赖快照覆盖已审阅目标哈希，可能吞掉外部编辑。
2. 查询前后两次 unlocked 检查不能排除多文件提交中间的混读。

修复后分别验证了两种选择顺序，以及查询持锁期间禁止 AKM writer 插入。另修复了 malformed baseline 可能被接受的问题。复审结论：**0 Critical、0 Important、0 Minor 未解决发现**。

## 明确限制

- 当前查询同步；异步 worker 与 job API 在阶段 2。
- 原子合并、自然语言提案编辑、暂缓恢复尚未实现；外部 Agent 可以生成结构化 edits。
- 模块 export/import、依赖闭包及 Vault 根目录外重新登记在后续阶段。
- 只有 UTF-8 Markdown/文本，不宣称支持 PDF/OCR。
- 每页一个主项目，不提供页面跨项目搬移。
- `.akm/ledgers` 记录来源与操作，没有完整 CO claim 风险/独立性模型。
- 用户 Obsidian 编辑不使用 AKM 锁；写入前置哈希会检测已变化目标，但无法提供 CO 的目录描述符固定和断电 durability 保证。
- 正文更新为全量替换，需要提案保留旧内容并人工审阅；本地模拟 server 测试不衡量 LLM 能否正确保留旧事实。后续真实 API 验证见下一节。

## 后续真实 API 验证与修复

上述 22 项、demo 和合成 benchmark 是第一次离线验证记录，保留其原始边界。之后接入用户提供的 API，通过 pi SDK 指定 `deepseek-v4-flash`，完成真实文档提案 → 选择写入 → 对话提案 → 指定页面更新 → 查询回答，并在 Obsidian 1.13.7 实际检查 Properties、正文与 related 跳转。

真实运行发现最佳三行摘要漏掉后续验证结果，导致回答仍引用历史状态。修复为问答展开有上限的正文，再用同一个问题、同一 Vault 调真实模型复验，回答已区分旧模拟验证与新增真实模型验证。旧事实、页面 ID 和来源链检查通过，根目录复制后的查询结果也一致。

补充了完整旧页上下文、生成期间哈希冲突检查、禁止模型更新未读取页面、workspace thinking 参数和安全调用统计。当前 **26/26 自动测试通过**，40-query 合成 benchmark 无回归；独立审查确认本轮范围无未解决发现。完整输入、原始提案、操作者修改、失败回答、复验回答与截图见 `docs/live-validation.md`，这些单次结果不作为普遍提取质量结论。

完整设计与本轮实现边界分别见 `docs/akm-design.md` 和阶段计划，未实现能力不会作为 MVP 命令暴露。
